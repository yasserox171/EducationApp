# هيكلة المشروع

هذا المستند يشرح البنية المختارة والأسباب وراءها. اقرأه قبل إضافة أي شاشة
جديدة حتى يبقى الكود متّسقًا.

---

## 1. إدارة الحالة: لماذا Riverpod؟

الاختيار: **Riverpod 2** (بدون توليد كود / `build_runner`).

| المعيار | Riverpod | Provider |
|---|---|---|
| الوصول للحالة خارج شجرة الودجات (المزامنة، طابور الإرسال) | مباشر عبر `ref` | يحتاج `BuildContext` |
| تركيب المزوّدات بعضها فوق بعض (مستودع ← DAO ← قاعدة بيانات) | مدمج ونظيف | يدوي عبر `ProxyProvider` |
| أخطاء وقت الترجمة بدل وقت التشغيل | نعم | لا (`ProviderNotFoundException`) |
| اختبار وحدات بلا واجهة | `ProviderContainer` | يحتاج ودجات |
| إلغاء تلقائي للموارد | `autoDispose` | يدوي |

التطبيق يحتوي منطقًا يعمل **خارج الشاشات** (المزامنة في الخلفية، طابور
الإرسال، التحميل)، وهذا بالضبط ما يتفوّق فيه Riverpod.

**لماذا بدون توليد كود؟** `riverpod_generator` و`freezed` يوفّران اختصارات،
لكنهما يفرضان تشغيل `build_runner` بعد كل تعديل. مشروع بهذا الحجم لا يحتاج
ذلك، والنماذج مكتوبة يدويًا مع `fromJson/toJson` و`fromDbRow/toDbRow`.

## 2. الطبقات

```
الواجهة (features/**/presentation)
    ↓ يقرأ/يستدعي
المزوّدات (Riverpod)
    ↓
المستودعات (data/repositories)  ← قرار: محلي أم شبكة؟
    ↓                    ↓
DAOs (sqflite)      خدمات API (dio)
```

قاعدة صارمة: **الواجهة لا تلمس Dio ولا sqflite أبدًا.** الشاشة تعرف
المستودع فقط، والمستودع وحده يقرّر من أين تأتي البيانات.

### شجرة الملفات

```
lib/
├── main.dart                  نقطة الإقلاع: env + قاعدة البيانات + الجلسة
├── app/
│   ├── app.dart               MaterialApp.router + العربية/RTL + السمة
│   └── providers.dart         كل مزوّدات البنية التحتية في مكان واحد
├── core/
│   ├── config/                env.dart (BASE_URL) + الثوابت
│   ├── error/                 AppException + محوّل أخطاء Dio
│   ├── network/               ApiClient, AuthInterceptor, NetworkInfo
│   ├── storage/               قاعدة البيانات، DAOs، التخزين الآمن، الملفات
│   ├── router/                GoRouter + المسارات
│   ├── theme/                 السمة (Material 3)
│   ├── l10n/                  النصوص العربية
│   └── utils/                 السجلّ، التنسيقات
├── data/
│   ├── models/                النماذج (JSON + صفوف قاعدة البيانات)
│   ├── remote/                خدمات API
│   ├── repositories/          منطق offline-first
│   └── sync/                  محرّك المزامنة وطابور الإرسال
└── features/
    ├── auth/                  الدخول + AuthController
    ├── student/               فضاء التلميذ
    ├── teacher/               فضاء الأستاذ
    └── shared/                ودجات ومزوّدات مشتركة
```

## 3. نمط Offline-first

### القراءة

```
اطلب المواد
   ↓
اقرأ من sqflite  ──────────────► أعِد النتيجة فورًا (حتى بدون إنترنت)
   ↓ (إن كان هناك اتصال والبيانات قديمة)
اسحب من الـ API → استبدل النسخة المحلية → أعِد الجديد
   ↓ (إن فشل الطلب)
أعِد النسخة المحلية بصمت. لا نسخة محلية؟ ارمِ الخطأ لتعرضه الواجهة.
```

### الكتابة (تقدّم التلميذ، إجابات الكويز، اختيار المستوى)

```
التلميذ يجيب على كويز
   ↓
اكتب في sqflite فورًا (الواجهة تستجيب مباشرة، بلا انتظار)
   ↓
ضَع عملية في جدول `outbox`
   ↓
SyncService يرسلها عند توفّر الاتصال (تراجع أسّي عند الفشل)
```

`dedup_key` يمنع تراكم الطابور: عشرات تحديثات التقدّم لنفس الدرس تُختصر
إلى أحدث واحدة (`progress:<lessonId>`). أما إجابات الكويز فلا تُدمج — كل
محاولة تُرسل لأن الأستاذ يحتاج كل النتائج، ومعرّف المحاولة (UUID محلي)
يعمل كمفتاح idempotency حتى لا تُحتسب مرّتين.

### حلّ التعارض

الأحدث يفوز (`updated_at`)، مع استثناء واحد: **الصف المحلي غير المرسل
(`is_dirty = 1`) لا يُدهس أبدًا** بما يأتي من الخادم.

### التحميل اليدوي

الفيديوهات **لا تُحمَّل تلقائيًا** أبدًا. المزامنة تحدّث قوائم المواد
والدروس والفقرات فقط. تحميل الفيديو يبدأ بضغطة التلميذ على زر «تحميل»:

1. سحب فقرات الدرس وتخزينها (النصوص والكويزات تصبح متاحة أوفلاين فورًا).
2. التحقّق من المساحة مقابل `MAX_OFFLINE_STORAGE_MB`.
3. تحميل كل فيديو إلى `<blockId>.part` ثم إعادة تسميته عند الاكتمال، حتى
   لا يُعتبر ملف نصف محمَّل جاهزًا للتشغيل.
4. الاستئناف عبر ترويسة `Range` إن دعمها الخادم.

الملفات في `ApplicationSupportDirectory/lessons/<lessonId>/` — لا في مجلد
المستندات، حتى لا تظهر للمستخدم في تطبيق الملفات ولا تُرفع إلى iCloud.

## 4. قاعدة البيانات المحلية

sqflite (لا Hive): البيانات علائقية بطبيعتها (مادة ← دروس ← فقرات) ونحتاج
استعلامات تجميع لصفحة «تقدّمي» ولإحصائيات الأستاذ.

| الجدول | الدور |
|---|---|
| `subjects`, `lessons`, `blocks` | المحتوى المخزَّن مؤقتًا |
| `media_files`, `lesson_downloads` | حالة التحميل على الجهاز |
| `lesson_progress`, `quiz_attempts`, `subject_levels` | بيانات التلميذ |
| `outbox` | طابور الإرسال |
| `kv` | أوقات آخر مزامنة |

الترقية عبر `onUpgrade` مع `schemaVersion`. عند تسجيل الخروج تُمسح كل جداول
المستخدم وتُحذف الملفات المحمَّلة — الجهاز قد يستعمله تلميذ آخر.

## 5. المصادقة

JWT مخزَّن في `flutter_secure_storage` (Keychain على iOS، EncryptedSharedPreferences
على Android). لا يُخزَّن في SharedPreferences ولا في قاعدة البيانات.

التبعية الدائرية بين `ApiClient` (يحتاج الرمز) و`AuthController` (يحتاج
`ApiClient`) مكسورة بـ `SessionHolder`: كائن صغير يعرفه الطرفان.

عند رد 401 من أي طلب: تُمسح الجلسة ويُحوَّل المستخدم لشاشة الدخول مع رسالة
«انتهت الجلسة». **البيانات المحلية لا تُمسح** في هذه الحالة تحديدًا: قد
يكون هناك تقدّم لم يُرسل بعد، وسيصل الخادم بمجرّد إعادة الدخول.

## 6. العربية و RTL

`locale: Locale('ar')` في `MaterialApp` يضبط `Directionality` لكل الشجرة
تلقائيًا — لا حاجة لتغليف يدوي. القواعد:

- استعمل `EdgeInsetsDirectional` و`AlignmentDirectional` لا `EdgeInsets.only(left:)`.
- حقول البريد وكلمة السر تُجبَر على `TextDirection.ltr`.
- النصوص في `core/l10n/ar_strings.dart` (ثوابت، لا `gen_l10n`، لأن اللغة
  واحدة حاليًا). إضافة لغة ثانية لاحقًا = تحويل هذا الملف إلى
  `AppLocalizations` دون تغيير مواضع الاستدعاء.

## 7. الإعدادات والأسرار

`BASE_URL` **غير مكتوب في الكود إطلاقًا**. يُقرأ من:

1. ملف `.env` (غير مرفوع للمستودع، مُدرج في `.gitignore`)، أو
2. `--dart-define=BASE_URL=...` لسلاسل البناء.

إن كان ناقصًا، يعرض التطبيق شاشة «الإعداد غير مكتمل» بدل الانهيار.

## 8. حالة البناء

**جاهز:** كل ما سبق — الطبقات، قاعدة البيانات، الشبكة، المصادقة، طابور
الإرسال والمزامنة، مدير التحميل، مستودع الأستاذ، الموجّه، السمة، شاشة
الدخول، وقائمة المواد للطرفين.

**التالي (بعد التأكيد):** شاشات قائمة الدروس، عارض الدرس بفقراته
(نص/فيديو/كويز)، اختيار المستوى، صفحة «تقدّمي»، الإعدادات، ومحرّر الدرس
وإحصائيات الأستاذ.
